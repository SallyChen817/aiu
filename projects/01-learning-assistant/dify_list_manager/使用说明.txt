多清单助手使用说明

运行与连接配置见上级 README.md。首次使用需要导入流程、绑定插件并配置自己的 API 密钥。

二、第一次创建每日待办
1. 点击聊天输入框，输入：明天早上要做啊，背单词、完成Python作业、整理材料。
2. 点击“发送”，等待出现“请确认本次操作”卡片。
3. 卡片会列出清单名称和三条事项，默认状态都是“未完成”。
4. 检查事项是否完整、清单是否正确。若不正确，点击“取消”，重新描述即可。
5. 正确则点击一次“确认保存”。这一批事项只需要确认一次，不必逐项确认。
6. 等到显示“已保存到……”才表示已写入数据库；左侧清单和进度会更新。
7. 刷新网页，已保存的清单和任务仍然存在。

“明天”“明早”会转换为按北京时间计算的具体日期清单，例如“2026-10-11 待办”。
同一天已有清单时会往其中追加，不会每次创建同名清单。
原来的“项目任务”和其他清单都会保留。

三、接着添加，不必重复说完整名称
1. 完成上面的保存后，当前清单就是刚才的每日待办。
2. 输入：再加一项买牛奶。
3. 核对确认卡片上的清单名称，点击“确认保存”。
4. 输入：再加两项，跑步、收拾书桌，也可以一次添加两项。
5. 同一清单已经有同名事项时，会提示重复；本次不会自动再次添加。

四、自定义其他清单
1. 输入：新建清单“旅行准备”：订车票、带雨伞、整理行李。
2. 检查卡片中的清单名称和事项，然后“确认保存”。
3. 若只想创建空清单，输入：新建一个空清单，名字叫“读书计划”。
4. 保存之后可以继续说“再加一项读第一章”。

五、切换和查询清单
方法一：点击左侧当前清单下拉框，选择需要的名称，等待助手完成切换。
方法二：在聊天里输入“切换到项目任务”或“查看明天待办”。
输入“我有哪些清单？”可列出全部清单名称。
查询不需要确认；之后的“再加一项”“这个完成了”针对当前清单。
新对话默认从“项目任务”开始；若已删除该清单，会显示当前存在的第一份清单。

六、更新状态
1. 先切换到事项所在清单。
2. 输入“背单词做完了，帮我记一下”。
3. 卡片应显示“背单词：未完成 → 已完成”。
4. 点击“确认保存”，等待数据库结果。
5. 也支持“把背单词改成进行中”“把背单词改回未完成”。
6. 多个同类修改可以一批提出，例如“背单词和整理材料都完成了”。
助手不会自动检测现实中是否完成，只记录你确认的状态。

七、删除事项或整份清单
删除一项：先切换对应清单，发送“删除买牛奶”，核对后确认。
删除多项：发送“删除买牛奶和跑步”，核对卡片中的事项后确认。
删除整份：发送“删除整个旅行准备清单”，卡片会列出清单及其全部事项；确认后一起删除。
其他清单不会跟着删除。只说“删除任务”但无法确定对象时，助手会追问。
如果不想执行，在卡片上点击“取消”，不会修改数据库。

八、确认卡片与刷新
确认卡片出现后，需要先确认或取消，再继续发下一条消息。
等待确认时刷新网页，卡片会恢复，仍可操作。
确认有效期为一小时；过期后重新提出请求。
若确认后网络中断，点击卡片中的“查看执行结果”，先核实结果，不要重复发送新增请求。
如果等待确认期间数据库被其他会话修改，旧提案会拒绝保存；重新查询后再提出操作即可。

九、还能问学习问题吗
可以，直接发送“Python列表怎么用”或“我今天有两小时，结合进度建议下一步”。
提出建议不会自动创建任务；想保存时明确说“把这些事项加入……清单”。
每条消息建议完成一种操作：一次批量新增、一次批量修改或一次批量删除。
本地小模型可能理解不准确，确认卡片就是核对最终操作内容的地方。

十、Dify 里面在哪里
1. 打开 http://localhost/，进入“工作室”。
2. 打开原来的“学习任务助手”，不是“清单助手验收（测试数据库）”。
3. 正式流程已由程序配置并发布，网页仍然连接这同一个应用。
4. 也可以在 Dify 的“预览”里直接聊天并确认；保存的数据与 8766 网页相同。
5. 主要节点：读取清单和任务 → 理解口语和操作 → 核对对象并生成确认内容 → 按操作分流。
6. 写入分支：确认整批操作 → 确认后一次性保存 → 重新查询执行结果 → 按数据库结果回复。
7. 取消分支和学习回答分支独立，不会绕过确认写入。
8. 后续修改节点后需要重新“发布”，8766 才会使用新版本。
9. 验收应用使用独立数据库，供测试使用，不是网页的第二个后台。


数据存储
使用自行初始化的 task_tool/tasks.db；导入工作流后重新选择 SQLite 凭据。提交版不包含任何个人清单或账号配置。
