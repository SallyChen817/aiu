# 本地学习任务助手

Ollama 提供 qwen3.5:4b，Dify Chatflow 编排查询、学习回答与人工确认，SQLite 保存任务，HTML/CSS/JavaScript 网页通过 Python 后端访问 Dify。

## 结构

| 路径 | 用途 |
| --- | --- |
| `test_Ollama.py` | 最初的 Ollama API 调用示例 |
| `本地部署web/` | 网页、后端和 Dify SSE 客户端 |
| `dify_list_manager/学习任务助手-多清单.yml` | 当前可导入工作流；内容为 JSON，也是合法 YAML |
| `dify_list_manager/planner.py` | 意图校验、操作提案和 SQL 生成 |

| `task_tool/` | 早期只读任务 API 与 OpenAPI 描述 |

| `WORKLOG.md` | 原项目工作日志 |

## 运行准备

Python Web 后端和旧查询工具仅依赖标准库。开发时使用 Dify 1.17.1 与 Ollama qwen3.5:4b；Dify 服务、模型文件和插件环境不包含在源码中，需要自行部署。参考工作流依赖的插件信息配置 Ollama、SQLite 和 Agent 策略。

在本项目目录执行以下命令建立空数据库。提交材料不携带原用户清单、进度和操作收据；没有清单时，可在助手中创建。

```powershell
python -c "import sqlite3,pathlib; c=sqlite3.connect('task_tool/tasks.db'); c.executescript(pathlib.Path('task_tool/schema.sql').read_text(encoding='utf-8')); c.close()"
```

将该数据库所在目录挂载到 Dify SQLite 插件能够读写的位置，按自己环境配置数据库路径。导入 `dify_list_manager/学习任务助手-多清单.yml` 后，需要重新选择本机模型供应商及 SQLite 凭据；导出中的原凭据 ID 已清空。检查读取、写入、保存复查和 Agent 查询分支，再发布应用。

后端默认连接 `http://localhost/v1`；若 Dify 不在此地址，需在 `本地部署web/server.py` 的 `make_server` 配置中调整。容器访问宿主机时使用环境支持的主机名并自行配置允许访问规则，不依赖原机器的网络地址。

```powershell
python -X utf8 本地部署web/server.py
```

浏览器打开 `http://localhost:8766`，通过“连接 Dify”填写当前环境的应用 API 密钥。密钥只写入被 Git 忽略的本地后端配置。先验证清单查询，再尝试“新建清单学习计划：背单词、完成作业”，核对确认卡片后保存。

## 实现与使用

新增、修改、删除均需要人工确认；取消不修改数据。任务状态来自 SQLite 中用户确认的记录，不自动判断现实任务是否完成。普通学习回答不自动写入待办。详细操作见[多清单使用说明](dify_list_manager/使用说明.txt)。

`task_tool/task_api.py` 是早期只读接口，当前 Chatflow 直接使用 SQLite 插件；复现旧接口时可执行 `python task_tool/task_api.py --host localhost`。若需要容器访问，须按自己的网络配置监听地址。OpenAPI 的服务器主机名是通用示例，不是原本机地址。

`build_workflow.py` 保留为工作流构建源码：在其目录运行 `python build_workflow.py --production` 会用脱敏模板生成 `built-dsl.json`，生成后仍须在 Dify 中重新绑定凭据。默认 QA 模式需要自己提供被忽略的 `qa-credential.json`。原来绑定本机账号并发布应用的维护脚本不收录。
