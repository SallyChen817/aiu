# 雷霆空战制作与展示详细步骤

本项目是一个在电脑浏览器中运行的飞机射击游戏，结合本地 Ollama 模型提供赛后点评。下面先说明项目的实现方法，再给出可以按顺序操作的现场展示流程。代码由 Codex 辅助实现；展示时应结合自己实际理解的内容讲解。

## 一 展示前先记住项目定位

可以用这段话开场：

> 我的创意作品是雷霆空战，一个支持积分累计和本地 AI 赛后点评的网页射击游戏。玩家控制飞机移动，主炮自动射击，也可以发射追踪导弹。游戏结束后，程序把实际战绩发送给本地部署的 Qwen 模型，由它生成建议。当前已经完成网页游戏和 Ollama 接口，Dify Agent 与 YOLO 控制是后续扩展方向。

与原任务的对应关系：

| 原任务内容 | 本作品对应情况 |
| --- | --- |
| 本地大模型部署与应用调用 | 复用已准备的 Ollama 和 Qwen3.5 4B，Python 调用其 API |
| 自己的应用 | HTML、CSS、JavaScript 实现的网页游戏 |
| 智能体搭建 | 游戏当前是直接模型调用，不能说已完成游戏内 Agent 工具调用 |
| YOLO 训练与实时部署 | 原文件夹已有独立项目，但尚未接入游戏 |
| 创意作品 | 飞机大战、积分成长、Boss 和赛后点评 |

## 二 项目具体怎么做出来

### 第 1 步 把创意拆成最小可展示功能

先确定一局游戏的完整流程：开始 → 移动和射击 → 击落敌机 → 获取补给 → 挑战 Boss → 结算 → AI 点评。

初版限定为一张太空战场、三种普通敌机、一个 Boss、普通子弹与追踪导弹两种攻击方式。先完成这条流程，再补充积分存档和配色解锁。

### 第 2 步 确定技术和文件分工

项目位置：`<PROJECT_ROOT>\雷霆空战`。

| 文件 | 具体职责 | 讲解时可以指出的内容 |
| --- | --- | --- |
| `index.html` | 放置战场画布、按钮、菜单、战绩和提示区 | 负责页面结构 |
| `style.css` | 太空风格、三栏排版、小屏幕适配 | 负责页面样式 |
| `game.js` | 游戏状态、运动、战斗、绘制、输入、AI 请求 | 负责交互和主要玩法 |
| `core.js` | 碰撞、连击倍率、积分、存档数据整理 | 将规则独立出来方便测试 |
| `server.py` | 提供网页并转发 AI 点评请求 | 浏览器与 Ollama 之间的本地接口 |

飞机和背景通过 Canvas 绘图，声音通过浏览器音频功能生成。运行游戏不需要安装前端框架，也不需要联网下载图片。Node.js 用于执行 JavaScript 测试，不是玩游戏的必要条件。

### 第 3 步 先写规则测试再实现规则

`core.test.cjs` 先规定预期结果，例如普通敌机基础分为 100、连击倍率不超过 3、最高分不会被较低成绩覆盖。最初规则模块还未创建，测试会失败；实现 `core.js` 后再运行测试确认结果。

规则中的圆形碰撞可以理解为：两个物体中心的距离，不大于两个碰撞半径之和，就认为发生碰撞。实际代码比较距离的平方，避免开平方。

这是简化的碰撞体，不是按飞机图片每一个像素判断碰撞。

### 第 4 步 建立游戏循环和状态

在 `game.js` 中查找 `frame`、`update`、`draw`：

1. `requestAnimationFrame` 请求浏览器在绘制时执行下一帧。
2. `frame` 计算本帧时间差。
3. 战斗状态下，`update` 更新飞机、子弹、敌机、计时器与碰撞。
4. `draw` 将最新状态画到 Canvas。

移动使用“速度 × 时间差”计算。代码还限制了单次时间差，减少卡顿后物体突然跳很远的情况。它没有承诺在所有设备上固定达到 60 FPS。

游戏有 `menu`、`playing`、`paused`、`result` 四个状态。暂停时停止战斗更新；切换窗口或隐藏页面时自动暂停，避免玩家离开页面仍不断受伤。

### 第 5 步 实现移动和自动射击

键盘监听方向键与 WASD。鼠标或触摸坐标会换算成画布内部坐标，再用于移动飞机。飞机位置限制在战场范围内，不能飞出屏幕。

主炮按计时器自动发射子弹，玩家主要负责移动和闪避。武器共有四级，分别发射 1、2、3、5 发子弹。拾取 W 升级，受伤则下降一级，但最低保留一级。

可讲：

> 自动射击降低了现场上手难度，观众只需要移动和释放导弹，就能体验完整玩法。

### 第 6 步 实现敌机与追踪导弹

普通敌机的生命值、速度和分数不同，生成频率会随时间变化。游戏在 30 秒和 60 秒切换空域，85 秒时生成旗舰。

查找 `fireMissile`：一次消耗一份弹药，发射两枚追踪弹，并设置约 0.45 秒冷却。导弹会根据附近有效敌人的位置调整飞行方向，命中后造成伤害。没有手动锁定按钮，也不是大模型在控制导弹。

### 第 7 步 完成补给与积分

| 项目 | 当前规则 |
| --- | --- |
| 初始状态 | 3 点生命、5 份导弹弹药、一级主炮 |
| 普通敌机基础分 | 100 分 |
| 快速敌机基础分 | 200 分 |
| 重型敌机基础分 | 500 分 |
| Boss 基础分 | 3000 分 |
| 连击窗口 | 每次击杀刷新 4 秒计时，超时或受伤中断 |
| 连击倍率 | 1—5 连击为 1 倍，6—10 为 1.5 倍，11—15 为 2 倍，16—20 为 2.5 倍，21 及以上为 3 倍 |
| W 补给 | 提升一级主炮，最高四级五发 |
| M 补给 | 增加 3 份导弹弹药，上限 20 份 |
| + 补给 | 恢复 1 点生命，上限 3 点，并提供短时保护 |
| 通关奖励 | 每点剩余生命额外奖励 500 分 |

实际击杀分数等于基础分乘以当前倍率。结算时把最终积分除以 100 后向下取整，得到新增星币。例：本局 12550 分，新增 125 星币。

### 第 8 步 保存成绩并避免重复结算

在 `core.js` 中，`settle` 保留新旧成绩中更高的最高分，同时累加星币和已结算局数。在 `game.js` 中，`finish` 使用 `settled` 标记防止同一局被多次结算。

保存位置是当前浏览器的 localStorage，键名为 `thunder-squadron-v1`，记录最高分、星币、局数、已拥有配色和当前配色。它没有用户账号，也不是云端排行榜。

同一浏览器同一访问来源下刷新可以恢复存档，但 `localhost`、`127.0.0.1`、不同端口和直接打开文件可能使用不同存储。展示时统一使用 `http://127.0.0.1:8877`。

### 第 9 步 把真实战绩接给本地模型

调用顺序如下：

```text
玩家结束一局
    ↓
game.js 汇总本局战绩
    ↓ 点击“请本地 AI 教官点评”
POST http://127.0.0.1:8877/api/review
    ↓
server.py 校验字段并组织提示词
    ↓
POST http://127.0.0.1:11434/api/chat
    ↓
Ollama 的 qwen3.5:4b 返回中文建议
    ↓
结算页面显示点评与模型来源
```

传递的是结构化 JSON，不是游戏录像。以下只用于解释字段，是示例数据：

```json
{
  "score": 12500,
  "kills": 45,
  "seconds": 110,
  "maxCombo": 18,
  "damage": 0,
  "missilesUsed": 4,
  "victory": true
}
```

其中 `damage` 表示玩家受伤次数，`missilesUsed` 表示消耗导弹弹药的次数，一次会发射两枚。模型看不到没有发送的轨迹、命中率等信息，因此不能据此编造结论。

Python 接口限制请求体大小，检查数值是否合法，并检查请求来源；它只监听本机。调用 Ollama 时关闭系统代理影响，设置超时。接口不是面向公网的完整生产服务。

### 第 10 步 处理模型失败和错误建议

结算页面默认先显示“本地规则分析”。只有真实模型调用成功，来源才显示为 `Ollama · qwen3.5:4b`。模型未启动、超时或返回异常时保留规则分析，并提示原因。

首次联调时，模型曾把受伤次数误解成输出伤害，还建议不存在的手动锁定操作。修正方式是在提示词中明确每个字段的含义，说明“主炮始终自动射击”，列出可以使用的控制和补给规则。

这能减少错误，但不能保证模型每次输出都完全正确。积分、碰撞、血量和奖励始终由程序计算，模型不能修改战绩。

### 第 11 步 用测试和浏览器检查结果

在 PowerShell 中运行：

```powershell
cd '<PROJECT_ROOT>\雷霆空战'
node --test core.test.cjs game.test.cjs
python -m unittest test_server.py -v
```

已记录结果为 7 项 JavaScript 测试、3 项 Python 测试通过。实际浏览器检查另覆盖页面、战斗、暂停、Boss、结算、存档与小屏幕布局。1366×768 首屏显示不完整的问题通过视口高度适配修复。

`browser-qa.cjs` 是开发验证脚本，需要另外准备隔离浏览器调试环境，普通演示不用运行。其 90 秒战斗和通关验证用了测试注入，截图中的测试成绩不能当作自己的真人操作成绩。

## 五 老师或面试官追问时怎么回答

**代码是不是全部自己写的？**

> 这个版本使用 Codex 辅助实现和测试。我提出了飞机大战、导弹、积分累计和便于演示的需求。展示前我会重点理解游戏循环、计分规则和模型接口，并根据自己实际参与的内容说明工作分工。

不要把尚未自行完成的修改或排查说成自己的独立经历。

**这个作品的 AI 在哪里？**

> AI 在赛后点评。游戏把真实统计发送给本地大模型，让它生成语言建议。飞机运动、碰撞和积分由普通程序执行。

**为什么不让大模型每一帧控制敌机？**

> 战斗要求连续、及时响应。模型请求有延迟，把它放在赛后分析更适合这个版本，也不会因为模型失败而中断游戏。

**这是智能体吗？**

> 当前是本地模型 API 接入，没有让模型自主选择或调用游戏工具，因此我把它叫 AI 点评功能。后续接 Dify Agent 查询战绩后，才进一步展示工具调用能力。

**追踪导弹是不是用了机器学习？**

> 没有。它根据敌机坐标选择附近目标，再调整速度方向，是游戏程序中的追踪算法。

**积分怎么保证不会重复增加？**

> 一局结束时先检查是否已经结算，已经结算就直接返回。这样不会因为多个结束事件重复增加星币。

**模型乱说怎么办？**

> 提示词解释战绩字段并限制建议范围，页面也标出来源。但生成内容仍需判断。模型没有修改积分的接口，所以错误点评不会改变游戏结果。

**测试通过是不是代表已经完全没有问题？**

> 不代表。已检查规则、接口和浏览器流程，但人工操作手感和难度还需要持续试玩。自动化通关检查采用了隔离测试注入，不等同于真人通关。

## 六 常见情况的处理

| 现象 | 现场处理 |
| --- | --- |
| 页面打不开 | 确认 Python 服务窗口还在，核对端口 8877；若服务已运行，直接刷新页面。 |
| 提示找不到 Python | 先确认电脑已安装 Python 并可在命令行调用；紧急时可直接打开 `index.html` 演示游戏，AI 点评暂不可用。 |
| AI 点评等待或失败 | 检查 Ollama 与模型是否可用；首次加载可能较慢。可先讲解调用流程，失败则如实展示规则分析和已有联调记录。 |
| 换窗口后飞机不动 | 游戏自动暂停，回到页面点击继续或按 P。 |
| 历史分数看起来消失 | 检查是否换了浏览器、无痕窗口、端口或地址；统一使用原来的浏览器和 `127.0.0.1:8877`。 |
| 配色点了没有变化 | 查看当前星币是否达到 100 或 200；配色入口在桌面右侧，窄屏会隐藏该栏。 |
| 服务启动提示端口占用 | 若当前地址能打开已有游戏就继续使用；否则先确认占用者，避免随意结束其他程序。 |

可以展示 `qa/ai-review-final.json` 作为接口联调样例，但要说明其中战绩是测试输入，不是现场这局的成绩。使用截图时同样说明是预先保存的测试画面。
