# 雷霆空战工作日志

项目名称：雷霆空战  
记录时间：2026 年 10 月 9 日至 10 日  
任务方向：在已有本地大模型基础上，完成一个方便现场展示的创意作品。

本次选择制作一个网页飞机大战，将射击游戏与本地大模型赛后点评结合。实现过程中使用 Codex 辅助生成代码、执行测试和排查问题。以下记录已经完成的工作；后续计划单独列出。

## 10 月 9 日 方案确定与初版制作

### 确定作品形式

根据任务总纲，第五部分允许制作游戏、软件、工具等创意作品。我希望作品能现场操作，有比较明显的视觉反馈，因此在怪兽防守、飞机大战和基地防守几个方向中选择了“雷霆空战”。

确定的主要功能是：控制飞机移动、自动射击、发射追踪导弹、消灭敌机、累计积分、拾取补给和挑战 Boss。同时增加本地模型点评，让前面部署的 Ollama 能在自己的应用中发挥作用。

初版采用网页形式，方便在浏览器中演示。游戏使用 HTML、CSS、JavaScript 和 Canvas；Python 提供本地服务；Ollama 使用已经准备的 `qwen3.5:4b` 模型。当前版本直接调用 Ollama，Dify 和 YOLO 没有接入游戏。

### 搭建界面和基础玩法

在原任务文件夹下新建“雷霆空战”目录，将游戏与已有 YOLO 项目分开保存。

页面中间是战场，左侧显示当前得分、击落数量、时间、历史最高分和星币，右侧显示战机、操作说明和补给说明。飞机、敌机、弹幕、星空和爆炸使用 Canvas 绘制，音效使用浏览器音频功能生成，不需要加载外部素材。

游戏流程包括待命、战斗、暂停和结算。主炮自动射击，玩家用鼠标或键盘移动，按空格发射追踪导弹。加入三种普通敌机，并设置 85 秒后生成旗舰 Boss。生命耗尽或击败 Boss 后进入结算。

### 加入积分和成长功能

普通敌机、快速敌机、重型敌机的基础分数分别为 100、200、500 分，Boss 基础分为 3000 分。连续击杀提高得分倍率，最高达到 3 倍；受伤或超过连击时间会中断连击。

补给分为三种：W 升级主炮，M 增加导弹，+ 恢复装甲。每局结算时将积分按每 100 分兑换 1 星币的规则累计，星币可以解锁战机配色。最高分和星币存入浏览器 localStorage，刷新后可以继续读取。

### 接入本地模型并做基础测试

结算页面先提供规则分析，再由用户点击按钮请求 AI 点评。前端把得分、击落数量、时长、最高连击、受伤次数、导弹使用次数和通关状态发给 Python，Python 再调用本机 Ollama 的聊天接口。

模型未启动或调用失败时，页面保留规则分析并提示原因，不影响游戏与结算。请求本地模型时显式绕过系统代理，沿用前期 Ollama 调试中确认的处理方式。

计分、碰撞和存档规则先编写测试，再实现代码；随后补充模拟战斗和接口测试。首轮尝试启动浏览器测试被自动审批拦截，因此当时只报告了自动测试结果，没有把浏览器实测写成已经完成。

## 10 月 10 日 浏览器实测与问题修正

### 完成浏览器和模型联调

继续执行后，本地游戏服务和独立测试浏览器成功启动。检查了桌面页面、手机尺寸页面、战斗画面、Boss、结算和刷新后的存档，并在真实结算界面调用了 Ollama 点评。

本机模型列表确认存在 `qwen3.5:4b`，真实请求成功返回中文点评。游戏服务地址为 `http://127.0.0.1:8877`，Ollama 地址为 `http://127.0.0.1:11434`。

### 处理发现的问题

| 问题 | 原因与处理 |
| --- | --- |
| 1366×768 屏幕上战场底部超出首屏 | 战场主要按宽度缩放，未充分考虑窗口高度。增加基于视口高度的战场宽度限制，同时压缩低高度屏幕的菜单排版。 |
| 模型把受伤次数误当成输出伤害 | `damage` 字段含义不够明确。在提示词中写明这是玩家受伤次数，并解释其余字段。 |
| 模型建议手动锁定等不存在的操作 | 在提示词中说明主炮始终自动射击、导弹自动追踪，并列出实际可用操作。修正后的样例能正确识别零受伤和通关情况。 |
| 本地模型探测请求返回 502 | 绕过系统代理后直接访问本机接口成功；游戏后端本身已使用绕过代理的请求方式。 |
| 早期模拟测试出现异常弹药数量 | 测试中的长期保护被修复补给改写，导致已结束的游戏仍被测试继续更新。修正测试驱动，在每一步设置测试保护并断言仍处于战斗状态。 |

### 验证结果

- 7 项 JavaScript 测试通过，覆盖计分、碰撞、存档、90 秒模拟战斗、导弹冷却、伤害保护、暂停及胜负结算等行为。
- 3 项 Python 测试通过，覆盖非法参数、来源校验、模型故障和模拟响应。
- 实际浏览器验证了开始游戏、导弹消耗、暂停恢复、Boss 生成、结算、存档刷新和不同尺寸布局，没有发现 JavaScript 运行异常。
- 本地 Ollama 的网页调用和修正提示词后的 API 复测均成功。

浏览器长时间战斗和通关检查使用隔离测试环境中的保护状态及测试触发，以提高验证效率。交付游戏不包含这些测试入口，因此这些结果不能写成已经真人完整通关，也不能代替难度平衡测试。相关截图和记录保存在 `qa` 文件夹。

## 当前成果与后续安排


这次实践中值得重点说明的是：实时游戏规则由程序计算，本地模型只负责赛后语言分析；结构化字段的解释会影响模型输出质量；浏览器实际尺寸检查也能发现模拟测试无法发现的布局问题。

展示前还需要自行熟悉操作并练习讲解。后续可以继续进行真人难度测试，再考虑通过 Dify Agent 获取战绩，或将已有 YOLO 笔检测结果用于控制飞机。以上是后续方向，当前不作为已完成功能展示。
