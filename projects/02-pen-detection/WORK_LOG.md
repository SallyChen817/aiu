### 做了什么

- 对照题目检查原来的项目。确认已有 Python 摄像头检测。
- 检查了哪些是训练输入、哪些只是输出图片和缓存，避免误删模型和数据。
- 原来只有 38 张训练图片和 8 张验证图片。查看样本后发现很多是相似的白桌场景，图片数量和场景变化都不够。
- 从以前竞赛资料的 `pen_dataset_merged` 中补充 300 张图片和对应标注，新增训练 240 张、验证 60 张。现在共 278 张训练图和 68 张验证图。

- 把代码和数据配置中的旧路径改成当前项目位置。
- 使用 YOLO11n-OBB 重新训练了 50 轮，生成 `runs/pen_obb/train1/weights/best.pt`。

遇到的问题

识别时能框出笔，但也会把背景框成笔。实际画面里有手、人物和天花板，与训练集里笔放在桌上的场景不同。不能只靠增加训练轮数解决这个问题。

后来把摄像头推理的置信度阈值从 0.25 调到 0.5，用来过滤低分误检。这只是减少显示出来的低分结果，不等于模型学会了新的背景。

当时的想法：先让自己的笔检测流程稳定运行。继续补数据时，要优先补实际摄像头拍到的场景，不是只增加相似图片。

## 2026-10-11：把摄像头和 YOLO 接到 FastAPI

### 实现过程

1. 先创建最小 FastAPI 程序，让浏览器显示 Hello World，确认服务能启动。
2. 把返回内容改成 HTML，加入开始按钮和状态文字。
3. 用 JavaScript 的 `fetch()` 请求 `/start`，让按钮能调用 Python。
4. 用 OpenCV 读取电脑摄像头，将每一帧编码为 JPEG，通过 `/video` 连续发给网页。
5. 在读取画面和 JPEG 编码之间加入 YOLO 推理，再用 `plot()` 画旋转框。
6. 在浏览器中看到了笔的检测框，说明训练模型、Python 推理和网页显示已经连起来了。

### 遇到的问题

- 启动时写了 `app:app`，但文件叫 `main.py`，因此找不到模块。改为 `main:app`。
- 浏览器出现拒绝连接。检查后发现 8000 端口没有后端服务运行，重新启动 Uvicorn 后继续测试。

### 当前思路：先用同一台电脑的摄像头和浏览器完成本地演示。手机摄像头和外置摄像头暂时不接，界面也先保持简单。
